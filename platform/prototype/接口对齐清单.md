## 关键接入约束

1. 课程发布前：首课资料已审核，每道题按当前内容版本审核；发布后不能直接覆盖，应先 clone 新修订版本。
2. 作业：已发布课程、同课程班级、1—5 道不同且当前审核通过的题目、未来截止时间。先创建带内容快照的草稿，再单独发布；中途审核内容改变会阻止发布。
3. 题目修订/审核：携带 `expected_digest`，审核/修订填写 `notes`；内容变化后重审。原型的复选框确认不能替代逐题审核。
4. 复核：`{submission_id, verdict, feedback, notes}`；`verdict` 只允许 `supported`、`contradiction`、`uncertain`。保留原始作答，新增复核事件，不改写原始答案。
5. 上传使用 JSON 的 `content_base64`，并附 `course_id`、`filename`、`source_url`、`license`；不是直接提交 multipart，也不能把本地 PDF 示例当成解析成功。
6. `GET /api/courses` 的 `chapters` 是章节数组，不是原型中的数字；`concepts` 是知识点数组。原型的 `students/progress/complete` 需要由 dashboard 合成或补后端聚合，不能原样套字段。
7. v0.9 使用 HttpOnly 会话 cookie；需要同源部署，或明确代理 `/api`。4180 原型服务器仅提供静态资源，没有 API 代理；不要把试点权限检查绕过去。
8. 后端无全局搜索接口。可对已授权返回的课程/资料做前端搜索；不能把未授权课程放进搜索索引。
9. 无保存任意章节富文本、通用站内通知、修改个人资料、按班级筛选的通用成员列表等独立接口。当前相关原型控件不应误标为可接入；需确定产品需求后补后端。
10. 学生端尚未设计：正式作业、练习/提示、解释提交、复核申请、学习任务/复测、学情历史、数据导出均已有后端能力，学生预览弹窗不能替代完整学生端。

## 不能沿用的历史接口

试点路径并未开放旧 `GET /api/teacher/workbench`、`/api/teacher/analytics`、`/api/teacher/eval-lab`、`/api/evaluations`、`/api/adaptive`、`/api/candidates`、`/api/rollback`，以及旧的概念直接修改路由。`/api/demo-login` 在试点模式明确拒绝。插件实验室的 `/setup` 也被试点层拒绝。对应能力应采用当前 dashboard、workbench item、候选/量规/策略等接口，不能照历史说明添加失效按钮。

## 建议接入顺序

- P0：登录/角色 → 授权课程 → 资料解析与审核 → 题目与量规审核 → 课程发布 → 班级邀请 → 作业快照发布 → 真实复核。完成教师主流程。
- P1：学生端、进度与学情、延期、连续会话、模型任务状态、投入与导出。
- P2：批量课程接入、插件/策略、诊断标注/量规验证、帮助向导、管理治理界面的迁移。
