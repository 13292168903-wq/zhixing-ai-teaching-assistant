# 三种课程接入方式 · v0.3

## 从哪里进入

运行 `start.ps1`，访问 http://127.0.0.1:3810 ，选择教师或管理员，打开侧栏“课程接入中心”。原“课程管理”的完整 JSON 课包导入也已接入同一草稿和审核流程。

本次实现的是本机原型。教师姓名、院系和教学班作为课程管理元数据保存，尚未连接学校身份认证、班级成员或选课系统；角色切换用于演示，不构成正式教师身份审核。原有两门示范课程继续可用并标明待教师确认。

## 方式一：模板开课

1. 选择理论与概念课、客观练习课或数值计算课。
2. 填写课程标识、课程名称、所属院系、负责教师和教学班。
3. 填写首个知识点的目标、摘要、来源 URL、来源文本与许可，以及练习、参考答案和评价要点。
4. 保存为草稿。数值模板需先由管理员安装 `numeric_check`。
5. 在“课程空间与发布”点击“审核本课程题目”，填写理由并逐题审核。
6. 返回接入中心，展开“补充完整课包与发布”，填写课程发布审核说明，发布课程。

表单用于一个知识点的快速试制。多个知识点使用完整课包 JSON，结构参考 `examples/course-pack.json`。来源和许可的检查目前是结构检查，原文支持关系与使用依据需教师确认。

已建的空草稿也可以在“操作目标”中选择后补齐。模板补齐或完整课包替换会覆盖该草稿的全部内容并清除旧题审核记录，页面会明确提示。已发布内容不接受直接覆盖。

程序接口：`POST /api/teacher/onboarding/template`，请求体参考 `examples/template-request.json`（数值课）。通过完整 JSON 接入：`POST /api/teacher/import`。

## 方式二：院系批量接入

页面提供 CSV 和 JSON 清单下载；本地样例为 `examples/courses.csv`。CSV 支持 UTF-8 BOM、带引号的逗号、双引号转义及换行。

| 字段 | 说明 |
| --- | --- |
| course_id | 必填，2—48 位，小写字母开头，仅字母、数字、下划线 |
| title | 必填，课程名称 |
| template_id | 必填，`concept`、`objective` 或 `numeric` |
| department | 必填，院系名称 |
| teacher | 必填，负责教师 |
| classes | 可选，用 `|` 分隔教学班；同一课程不得重名 |
| version | 可选，默认 `0.1.0` |
| topics_json | 可选，知识点数组的 JSON；复杂资料建议直接使用 JSON 清单 |

JSON 清单支持数组，或 `{ "rows": [...] }`；每一行与 `template-request.json` 结构相同。每批 1—50 门课；每门最多 30 个知识点、50 个教学班。当前完整课包最多 200 条练习，请求体最多 1 MiB，较大资料应拆分整理。

操作：选择文件 → 预检 → 查看每行结果 → 确认整批创建。预检不写入；内容变化须重新预检。依赖缺失、课程标识重复或任意一行不合法时不写入任何课程。数据库事务失败也会回滚整批内容与审计。

不带 topics 的清单创建空课程空间，后续由教师补齐。带 topics 的清单可以批量导入课程内容，但仍需逐课审核发布。不会因为清单导入成功而声称教学资料已获教师验证。

接口：

- `POST /api/teacher/onboarding/preview`：`{ "rows": [...] }`，返回逐行结果与 digest。
- `POST /api/teacher/onboarding/batch`：提交同样的 rows 和返回的 digest。
- `GET /api/teacher/onboarding`：模板、接入课程、教学班元数据、插件目录。

## 方式三：插件扩展

1. 管理员打开“03 · 插件安装与课程绑定”，安装数值容差核验插件。
2. 教师选择草稿课程和已安装评阅插件，保存绑定；数值模板会自动声明 `numeric_check` 依赖。
3. 题目采用 `assessment_mode: "plugin"` 并声明能力和配置。
4. 审核发布后，正常的 `verify_submission` 工具调用会执行对应的服务端评阅处理器。DS-H 调用接口保持不变。

```json
{
  "assessment_mode": "plugin",
  "assessment": {
    "capability": "numeric_check",
    "config": {
      "target": 3,
      "absolute_tolerance": 0.001,
      "relative_tolerance": 0
    }
  }
}
```

正确条件为 `abs(answer-target) <= max(absolute_tolerance, abs(target)*relative_tolerance)`。当前插件接受有限实数与科学计数法，不解析表达式、公式、单位换算或代码。评分目标与容差不进入学生题目响应。答案正确、解释矛盾和提示依赖仍分别记录；数值匹配不等于教师确认全面掌握。

同一插件可以绑定多门课程，课程不共享学生学习状态。插件与绑定写入 SQLite，重启后先恢复插件，再装配课程。

管理员可上传 `examples/numeric-plugin.json`，为现有受信 `numeric_tolerance` 处理器注册另一个能力标识；这属于处理器复用。新算法需开发者添加可信服务端实现和核验测试。当前不提供任意脚本上传执行、远程插件下载或自动安装 npm 包。

扩展处理器的最小契约：

```js
// 在 src/extensions.mjs 中维护可信实现。
const handler = {
  validate(config) { /* 校验参数；无效时抛出明确的 400 错误 */ },
  assess(answer, config) {
    return { correct: true, method: 'your_method' };
  }
};
// 注册能力元数据，并将同一标识映射到 registry.assessments。
// 必须通过依赖校验、答案边界、提示依赖、跨课隔离和重启测试。
```

接口：`POST /api/admin/plugins/install`，请求 `{ "plugin_id": "numeric_check" }` 或 `{ "descriptor": {...} }`；`POST /api/teacher/onboarding/:id/plugins`，请求 `{ "capabilities": ["numeric_check"] }`。

## 发布、持久化和边界

新接入课程默认草稿，学生课程列表、问答、练习与学情入口均不可访问。发布要求课程包含资料和题目、每个知识点有证据与练习、所有题目审核通过、插件依赖已安装，并填写发布说明。

完整课包接口：`GET /api/teacher/onboarding/:id/pack`；替换草稿：`POST .../:id/content`；通过模板补齐：`POST .../:id/template`；发布：`POST .../:id/publish`。

数据位于 `platform/var/platform.sqlite` 的 `course_catalog`、`onboarding_batches`、`installed_extensions` 表，并记录审计。保留读取历史 `var/course-packs/` 的兼容能力；新导入统一写数据库。备份时应关闭服务后备份整个 var 目录。

该发布流程是内容审核门禁，尚不代表新课程已经配备独立开发／验证／封存评测。自动文档解析、学校人员授权、实际班级选课、同一课程多版本迁移和逐课独立评测，属于后续校园部署工作。
